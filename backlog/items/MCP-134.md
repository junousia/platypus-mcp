# MCP-134 Add Pi product steering workflow

## Goal

Let users redirect the product intentionally through Pi without manually editing guidance files or backlog items.

## Implementation Contract

Add a steering flow for prompts like “move the product toward X” or “change direction”. Pi should collect the new direction, compare it against current project guidance and backlog state, ask the manager agent for proposed documentation/backlog changes, present those changes for approval, and then persist accepted updates.

The workflow should preserve old context when useful and make tradeoffs visible instead of overwriting project intent silently.

## Acceptance

- Pi can start a steering session from a command or natural-language prompt context.
- The session summarizes current direction, proposed new direction, affected docs, affected backlog items, and unresolved decisions.
- Approved steering updates persist to repository guidance and backlog items through typed tools or deterministic updates.
- The flow records follow-up backlog items or findings for unresolved implications.
- Tests cover simple direction update, conflicting direction update, and rejected proposal paths.
