# MCP-150 Improve PR workflow awareness after source PR is merged

## Goal

Help hosts notice when the PR associated with the current branch was already merged so follow-up implementation commits are routed to a new PR or branch intentionally.

## Implementation Contract

Explore lightweight host guidance or Pi workflow affordances for detecting/reporting that the current branch's PR is merged before pushing more work. Do not require GitHub CLI for core MCP behavior; keep provider-specific checks in host/Pi guidance or optional workflow documentation.

## Acceptance

- Workflow guidance explains what to do when a branch PR is merged but local follow-up commits are added.
- Any Pi affordance remains optional and degrades gracefully without GitHub credentials or gh installed.
- No core MCP tool depends on GitHub network access.
- Docs or tests cover the intended behavior.
