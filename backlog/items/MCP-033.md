# MCP-033 Add generic external reference model

## Goal

Let backlog items reference work intake and reporting surfaces such as GitHub,
Linear, Jira, GitLab, support tickets, specs, or local docs without coupling the
backlog schema to one provider.

## Implementation Contract

Extend the strict backlog item schema with a generic `external_refs` field.
References must have provider, kind, stable id, URL or locator, optional source
hash, and import metadata. Keep the local backlog item as the executable
snapshot. Do not allow external refs to replace required local goal, contract,
acceptance, dependencies, worker, or owned surface fields.

## Acceptance

- Backlog validation accepts well-formed external refs and rejects malformed or
  unknown reference fields.
- `create_backlog_item` can write external refs through typed params.
- `list_backlog` and `inspect_work_queue` expose external refs without making
  provider-specific assumptions.
- Documentation explains input, execution, and reporting surfaces.
- Tests cover valid refs, invalid refs, and backward compatibility for items
  without refs.

## Notes

External systems should feed local executable backlog snapshots. They should
not silently mutate active execution contracts.
