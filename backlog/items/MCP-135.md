# MCP-135 Add Pi post-implementation review workflow

## Goal

Make completion in Pi include a structured review of whether the work matched the story, met project standards, and produced follow-up findings.

## Implementation Contract

After implementation and verification, Pi should guide the manager agent through a concise post-implementation review: compare changes against acceptance criteria, summarize verification evidence, identify unresolved findings, propose follow-up backlog items, and then complete the item with the correct Platypus tool.

This should make findings and follow-up work hard to forget without forcing noisy ceremony for trivial direct work.

## Acceptance

- Pi can trigger a post-implementation review for direct and worker-handoff work.
- Review output covers acceptance criteria, changed files, verification, findings, and follow-up proposals.
- The flow can create required findings or follow-up backlog items before completion when approved.
- Completion calls include evidence and summary derived from the review.
- Tests cover clean completion, completion with findings, and completion with follow-up item proposals.
