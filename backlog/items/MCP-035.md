# MCP-035 Import GitHub issues as backlog snapshots

## Goal

Import selected GitHub issues into local backlog items so GitHub can be used as
an intake surface while Platypus keeps a stable executable contract in the repo.

## Implementation Contract

Add a GitHub issue intake adapter behind the generic external adapter boundary.
Support owner, repository, state, labels, milestone, and limit filters. Map
issue title, body, labels, URL, number, and timestamps into draft backlog
candidates with GitHub external refs and source hashes. The first version may
require host-provided issue JSON or a configured command/provider boundary, but
the MCP tool contract must stay provider-neutral where possible and fail with
clear recovery guidance when credentials or network access are unavailable.

## Acceptance

- GitHub issue candidates can be listed/imported without creating duplicate
  backlog items for the same issue.
- Imported items validate as normal backlog items and include GitHub external
  refs with source hashes.
- Label mapping to priority, type, area, and owned surfaces is deterministic
  and documented.
- Network/auth failures are structured and do not create partial backlog files.
- Tests cover import from fixture JSON, duplicate detection, label mapping, and
  invalid issue payloads without requiring live GitHub.

## Notes

Keep this as import/snapshot first. Live bidirectional sync belongs in a later
item after the local execution contract is stable.
