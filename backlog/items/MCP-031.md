# MCP-031 Add durable task and project leases

## Goal

Make local multi-process coordination explicit now so the runtime can later
support multiple hosts and workers without redesigning task ownership.

## Implementation Contract

Add durable lease records for project-level and task-level ownership. Leases
must include owner identity, scope, expiry, renewal metadata, and safe release
semantics. Dispatch, handoff preparation, worker start, integration, and cleanup
must respect active leases and return recovery guidance when a lease blocks the
operation.

## Acceptance

- A task or project operation can acquire, renew, inspect, and release a lease.
- Conflicting dispatch, integration, or cleanup attempts are blocked with
  structured recovery guidance.
- Expired leases can be reclaimed deterministically.
- Lease state is visible through inspection or event replay.
- Tests cover concurrent acquisition attempts, expiry/reclaim, release, and
  blocked mutations.

## Notes

Leases should be implemented for local SQLite first, but the semantics must be
portable to a central store such as Postgres or a log-backed coordinator later.
