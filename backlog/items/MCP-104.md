# MCP-104 Mark optional and transition-sensitive schema hints

## Goal

Make schemas_likely_needed_next distinguish required next tools from optional helpers and stay accurate after state transitions.

## Implementation Contract

Extend schema discovery hint data with optionality or intent metadata, and tune queue/session/completion hints so optional helpers such as record_verification_evidence are not presented as required. Ensure hints after create/complete transitions point to the current next step rather than stale phase assumptions.

## Acceptance

- Schema hints include whether a tool is required, optional, or recovery-only for the current phase.
- direct_ready hints mark record_verification_evidence as optional when complete_backlog_item can carry verification fields directly.
- Completion or post-transition responses suggest inspect_work_queue or the actual next ready item where appropriate.
- Tests cover empty_backlog, direct_ready, and post-completion hint output.
