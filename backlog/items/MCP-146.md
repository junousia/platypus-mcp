# MCP-146 Serialize or retry concurrent Platypus state mutations

## Goal

Prevent parallel host operations such as multiple finish_work calls from failing with transient SQLite database locked errors.

## Implementation Contract

Review SQLite connection and transaction behavior for mutating tools. Add a bounded busy timeout, retry, or serialized write strategy appropriate for local-first operation, with tests that simulate or exercise concurrent mutations. Do not hide persistent lock or corruption problems; return structured recovery after bounded retries fail.

## Acceptance

- Concurrent finish_work or comparable mutating calls no longer fail on ordinary transient SQLite lock contention.
- Persistent lock failures still return structured errors with recovery guidance after a bounded wait/retry.
- Tests cover concurrent or lock-contention behavior.
- `make check` passes.
