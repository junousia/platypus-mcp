# MCP-062 Reduce test4 workflow friction

## Goal

Address the concrete workflow friction found in the test4 exercise: runtime database noise, rigid backlog type input, and plan requirements for trivial scaffold work.

## Implementation Contract

Keep strict persisted schemas and safe dispatch behavior, but make host-facing tools more forgiving where the intent is unambiguous. Ignore Platypus runtime state in Git readiness even if a user accidentally tracked it, generate stronger default ignore rules for common runtime/build noise, accept common backlog item type aliases, and classify simple single-surface scaffold/setup work as direct.

## Acceptance

- Git readiness ignores tracked `.platy/platypus.sqlite3` changes.
- New project `.gitignore` includes `.platy/` and common Python/Node generated files without overwriting user rules.
- `create_backlog_item` accepts `type: backlog` and writes a valid persisted type.
- Simple single-surface scaffold/setup backlog items are direct and do not require a task plan.
- Tests cover the above behavior.
