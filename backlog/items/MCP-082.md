# MCP-082 Context-aware validation next actions

## Goal

Stop validation tools from nudging hosts toward committing planning artifacts when the next executable path is direct work and the commit is optional.

## Implementation Contract

Update validation and task-plan write responses so `next_action` depends on the effective queue state and execution policy. Direct-ready items should receive direct-edit next actions. Worker-handoff items should still receive planning-artifact commit guidance when it matters for worktree dispatch safety.

## Acceptance

- `validate_backlog` does not emit unconditional commit-before-dispatch guidance.
- Direct-ready queues recommend `prepare_work` and `complete_backlog_item` flow.
- Worker-handoff queues still surface planning commit guidance when uncommitted planning artifacts could affect isolation.
- Tests cover direct-only, worker-handoff, and mixed queue next actions.
