# MCP-042 Define domain-shaped project state boundary

## Goal

Define the backend-independent ProjectState boundary so product code depends on Platypus domain operations instead of SQL-shaped repositories.

## Implementation Contract

Document the target ProjectState architecture, backend responsibilities, atomic lifecycle guarantees, capability model, and migration rules. Explicitly deprecate repository/table-shaped public boundaries for new product logic.

## Acceptance

- docs/storage.md describes ProjectState as the public storage boundary and SQLite as one implementation.
- The docs define atomic domain operations such as dispatch, prepare assignment, complete assignment, next safe action, evidence, findings, and reconciliation.
- The docs include a migration rule that rusqlite and SQL query construction must remain private to SQLite backend modules.
- The README storage section points to the new boundary without implying SQLite is the product boundary.
