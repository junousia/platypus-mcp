# MCP-036 Plan external reporting and sync policies

## Goal

Define how Platypus should later report results back to GitHub, Linear, Jira,
or other systems without making external trackers the hidden runtime source of
truth.

## Implementation Contract

Document explicit policies for import snapshots, source drift detection,
conflict handling, issue comments, PR links, closure updates, external status
mirroring, and bidirectional sync boundaries. Include plugin considerations and
security rules for credentials, redaction, rate limits, and provider failures.

## Acceptance

- Documentation defines import-only, mirror, bidirectional sync, and
  external-source modes with clear tradeoffs.
- The recommended first product mode is import-only with explicit reporting
  actions.
- The docs specify what can be automated safely and what requires approval.
- Diagrams show how external intake, local execution, and external reporting
  relate.
- The roadmap lists the next implementation item after GitHub issue import.

## Notes

This keeps the integration roadmap extendable without committing too early to a
tracker as the source of truth.
