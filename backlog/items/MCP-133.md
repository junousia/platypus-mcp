# MCP-133 Add Pi implementation plan review workflow

## Goal

Give users and manager agents a lightweight implementation review step before work starts, especially for non-trivial backlog items.

## Implementation Contract

Add a Pi workflow that asks the manager agent to produce a short implementation plan: expected files/modules, test strategy, risks, verification command, whether a durable task plan is needed, and what evidence should prove completion. For direct items this may be response-local guidance. For standard/full items it should create or update strict task plans.

The workflow must avoid fake deterministic planning. It should use project standards and backlog content as context, then rely on the manager agent for judgement.

## Acceptance

- Pi can request an implementation plan review for the next ready item or a selected backlog item.
- The review clearly states direct, standard, or full planning expectations.
- Durable task plans are created only when the workflow requires them or the user approves them.
- Review output includes expected surfaces, tests, risks, and completion evidence.
- Tests cover direct response-local planning and durable task-plan creation paths.
