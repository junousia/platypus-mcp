# MCP-130 Add Pi project direction wizard

## Goal

Make Pi guide first-time project setup by capturing product direction, quality expectations, stack preferences, and working agreements before backlog work begins.

## Implementation Contract

Add a Pi-guided setup flow that asks concise questions about the project domain, users, stack, deployment target, testing expectations, UI/UX expectations, security/privacy concerns, performance constraints, and preferred repository structure. The output must become durable repository guidance rather than hidden chat state.

The flow should write or update project guidance files through Platypus-controlled tools or deterministic file updates, then ask the manager agent to use those files when shaping backlog items. Keep the flow usable in non-interactive or partially completed projects by showing current answers and allowing revision.

## Acceptance

- Pi exposes a guided project direction flow for new and existing projects.
- The flow records durable guidance in repository files such as `AGENTS.md`, `WORKFLOW.md`, `docs/product.md`, `docs/architecture.md`, or `docs/testing.md`.
- Users can inspect and revise the captured direction later without rerunning the whole setup.
- The manager prompt receives a concise summary of the current project direction during relevant planning turns.
- Tests cover fresh setup, existing guidance, partial answers, and revision behavior.
