# MCP-088 Reconcile stale lifecycles for closed items

## Goal

Make reconciliation distinguish stale active task lifecycles attached to backlog items that are already closed, so closed work does not produce misleading planning-approval or incomplete-evidence gaps.

## Implementation Contract

Update reconciliation to classify nonterminal task lifecycles for closed backlog items as stale closed-item lifecycle gaps with concrete recovery guidance. Avoid reporting planning approval or evidence-for-incomplete-task gaps for those stale closed-item task IDs. Keep the change read-only and deterministic; do not delete runtime records in reconciliation.

## Acceptance

- reconcile_project reports stale closed-item lifecycles with the affected task IDs and source item IDs.
- Closed items with stale queued tasks no longer produce planning_approval_missing gaps.
- Evidence attached to stale tasks for closed items no longer produces evidence_for_incomplete_task gaps.
- Queue status does not count stale tasks for closed items as active runnable work.
- Recovery guidance explains that reconciliation is read-only and points to the lifecycle cleanup or ignore path without implying backlog reopening.
- Tests cover SQLite and memory reconciliation behavior for closed items with stale task state.
