# MCP-041 Storage backend capability probe

## Goal

Add a small deterministic probe that verifies the documented runtime backend
contract through repository traits before any second backend is selected.

## Implementation Contract

The probe should exercise transactions, ordered replay, idempotency/conflict
behavior, leases, migration repeatability, project identity, and recovery
inspection through the same storage boundary used by MCP tools. It should be
usable in tests and optionally exposed as a read-only diagnostic tool if that
helps hosts explain backend readiness.

## Acceptance

- The probe verifies event/transition/task replay ordering with a monotonic
  key.
- It verifies conflicting lease acquisition and idempotent or conflict-safe
  mutation behavior.
- It verifies schema initialization/migration can be run repeatedly.
- Failures are reported as structured capability gaps, not panics.
- Documentation says passing this probe is required before adding a shared
  backend such as Postgres.

## Notes

This keeps the distributed-storage path concrete without prematurely choosing
or integrating a non-SQLite backend.
