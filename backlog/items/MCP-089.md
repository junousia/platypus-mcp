# MCP-089 Remove misleading generated implementation contracts

## Goal

Make backlog creation avoid tautological implementation_contract text so generated backlog items do not look more specific than they are.

## Implementation Contract

Change create_backlog_items and related guidance so omitted implementation contracts either stay clearly absent/derived as guidance-only metadata or are replaced by an explicit, non-misleading placeholder policy. Preserve strict validation and make the resulting markdown/schema behavior obvious to agents.

## Acceptance

- create_backlog_items no longer writes a tautological implementation_contract that repeats the goal as authoritative guidance.
- Validation and schema descriptions explain when implementation_contract is required, optional, or derived.
- Existing callers that provide a real implementation_contract keep the exact supplied value.
- Tests cover omitted, provided, and invalid contract cases.
