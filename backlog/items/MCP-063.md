# MCP-063 Reduce test5 integration friction

## Goal

Address the workflow friction found in the test5 exercise: repeated integration conflicts, manual file checkout, forced verification evidence, stale worktrees, and opaque ready-task limits.

## Implementation Contract

Keep Git operations explicit and audit-friendly, but make the safe path easier than manual recovery. Integration must detect unfinished Git operations before starting, return conflict guidance without leaving `MERGE_HEAD` behind, support an explicit file-level apply strategy for worker branches, allow per-call unverified integration when policy permits, and optionally clean integrated worktrees. Dispatch and queue inspection should explain how many items are ready and why dispatch stopped.

## Acceptance

- Integration refuses an existing unfinished merge/rebase/cherry-pick with clear recovery guidance before mutating.
- Merge conflicts are reported with conflicting files and the repository is returned to a clean non-merge state.
- `integrate_worker_result` supports an explicit `apply_changed_files` strategy that safely applies worker branch files without requiring manual `git checkout`.
- `integrate_worker_result` can bypass missing verification evidence with an explicit per-call flag, while strict workflow config can still require evidence by default.
- Successful integration can clean the task worktree and clear workspace metadata when requested.
- `dispatch_ready_work` and `inspect_work_queue` report ready/blocked counts and selection-limit guidance so default limits are visible.
- Tests cover integration conflict handling, file-level apply integration, cleanup-after-integration, verification bypass, and queue visibility.
