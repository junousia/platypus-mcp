# MCP-129 Document the Pi showcase workflow

## Goal

Make Pi the clearest documented example of how Platypus should feel when integrated deeply into a host.

## Implementation Contract

Update the public docs to present Pi as the showcase integration: first-run bootstrap, status widget, typed tools, happy-path workflow, completion behavior, feedback exercise, and troubleshooting. The docs should distinguish Pi-native UX from generic MCP host behavior without implying the Rust server depends on Pi.

Keep the docs concise and exact. Prefer one complete example flow over broad tool catalogs.

## Acceptance

- README explains why Pi is the showcase integration and how to try it quickly.
- Install docs include Pi setup, check, package/binary resolution, and recovery guidance.
- Workflow docs include one end-to-end Pi-native example from project idea to completed backlog item.
- Tool docs explain which Pi commands map to which MCP tools.
- Documentation states that the Rust MCP server remains host-neutral and Pi is a first-class UI/control surface on top.
