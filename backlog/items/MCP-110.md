# MCP-110 Compact batch backlog creation responses

## Goal

Make create_backlog_items easier for agents to scan during normal operation while preserving verbose debugging output when requested.

## Implementation Contract

Add a documented response detail mode or equivalent input that lets create_backlog_items suppress full generated Markdown previews in successful non-preview writes, while keeping atomic validation and exact created item metadata. Consider an optional queue snapshot flag only if it can be implemented deterministically without hiding validation failures.

## Acceptance

- create_backlog_items supports a compact successful write response that includes created IDs, paths, inline validation status, and next action without full Markdown bodies.
- Verbose or preview behavior still exposes generated Markdown for review and debugging.
- The response clearly states that validate_backlog is optional after successful typed creation unless files were manually edited.
- Tests cover compact, verbose or preview, and failed atomic batch behavior.
