# MCP-120 Make release publishing idempotent

## Goal

Allow GitHub release workflow reruns after partial publishing without failing on package versions that were already uploaded.

## Implementation Contract

Before real upload steps, inspect crates.io and npm for the package version declared in the checked-out metadata. If the version already exists, skip only that upload while keeping validation and downstream jobs successful. Missing versions must still publish normally, and registry lookup failures must fail clearly instead of silently skipping.

## Acceptance

- Release reruns skip crates.io upload when `platypus-mcp` version already exists.
- Release reruns skip npm upload when `platypus-pi` version already exists.
- Missing crate or npm versions still run the real publish step.
- Registry lookup failures report a clear error and do not masquerade as successful publishes.
- Documentation explains rerunning the workflow after a partial release.
