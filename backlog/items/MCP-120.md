# MCP-120 Make release publishing idempotent

## Goal

Allow GitHub release workflow reruns after partial publishing without failing on package versions that were already uploaded.

## Implementation Contract

Before real upload steps, make already-published versions safe to rerun. For crates.io, let `cargo publish` be the authority and treat only its duplicate-version response as a successful skip. For npm, inspect the package version before upload and skip only when npm reports the exact version already exists. Missing versions must still publish normally, and unexpected registry or publish failures must fail clearly instead of silently skipping.

## Acceptance

- Release reruns treat the crates.io duplicate-version publish response as success.
- Release reruns skip npm upload when `platypus-pi` version already exists.
- Missing crate or npm versions still run the real publish step.
- Registry lookup failures report a clear error and do not masquerade as successful publishes.
- Documentation explains rerunning the workflow after a partial release.
