# MCP-132 Add Pi story quality review workflow

## Goal

Make Pi review user stories and backlog item proposals before execution so vague work is clarified early.

## Implementation Contract

Add a visible story review flow that checks whether a story has a concrete goal, testable acceptance criteria, clear owned surfaces, explicit dependencies, appropriate planning mode, and expected completion evidence. The review should present questions or recommended edits to the user and manager agent instead of silently rewriting intent.

The MCP side may expose deterministic validation or inspection helpers if needed, but judgement belongs to the manager agent using project guidance.

## Acceptance

- Pi can trigger a story review for draft text, existing backlog items, or manager-proposed backlog items.
- Review output distinguishes blocking issues from improvement suggestions.
- Review prompts reference the current project direction and engineering standards.
- Approved revisions can be turned into typed backlog item creation or update calls.
- Tests cover vague, acceptable, dependency-blocked, and over-broad story examples.
