# MCP-052 Install spec-driven guidance during project initialization

## Goal

Make every newly initialized Platypus project guide MCP-enabled coding hosts into a controlled spec-driven workflow without requiring a bespoke UI or manual process knowledge.

## Implementation Contract

Extend initialization and host guidance so a fresh project advertises Platypus as the default planning and execution control surface. The scaffold should explain goal intake, backlog drafting, task-plan requirements, worker handoff, evidence, findings, integration, and recovery in files that coding agents naturally read. MCP resources/prompts should expose the same spec-driven workflow to hosts that consume MCP guidance directly. Keep runtime state out of generated markdown and preserve existing deterministic backlog/task-plan tools.

## Acceptance

- init_project creates or preserves a project-level AGENTS.md that instructs coding agents to use Platypus MCP before ad hoc edits.
- init_project writes stronger WORKFLOW.md and backlog guidance describing goal -> backlog -> task plan -> dispatch -> evidence -> integrate flow.
- MCP resources and prompts include spec-driven development guidance for turning free-form goals into controlled backlog and task-plan artifacts.
- Tests cover the initialized scaffold and the new guidance resource/prompt.

## Notes

Created from the product goal that Platypus MCP should silently let vibecoders start structured, sustainable spec-driven development in any initialized directory.
