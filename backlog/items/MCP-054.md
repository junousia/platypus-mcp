# MCP-054 Expose backlog inventory and closure reasons

## Goal

Let MCP hosts explain why the work queue is empty by inspecting all backlog items, their dependency state, and Git-trailer closure status.

## Implementation Contract

Add a read-only backlog inventory tool or extend the existing backlog listing surface with a typed all-item view. The result must include each item id, title, priority, dependency readiness, whether the item is closed by reachable Platypus-Closes trailers, and a concise reason when it is not runnable. Keep runnable queue behavior unchanged and avoid reintroducing a manual backlog index.

## Acceptance

- A host can inspect active and closed backlog items without reading markdown files directly.
- Closed items include a closure reason derived from Git trailers.
- Blocked items explain which dependencies are still open.
- The existing runnable list and work queue behavior remain backward compatible.
- Tests cover an empty runnable queue with closed historical items and a blocked item explanation.

## Notes

Created after the queue became empty while valid historical backlog files remained. Hosts need a better explanation than `No runnable backlog items`.
