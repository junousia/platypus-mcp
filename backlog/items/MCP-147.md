# MCP-147 Make finish_work recovery atomic around evidence recording

## Goal

Avoid partial finish_work lifecycle updates when later verification evidence recording fails, or make the partial state explicitly recoverable without manual state edits.

## Implementation Contract

Inspect finish_work ordering for assignment completion, evidence recording, findings, and integration guidance. Prefer a transaction or resumable idempotent recovery path so callers can retry finish_work safely after evidence/storage failures. Add tests for a failure after assignment completion but before evidence recording.

## Acceptance

- A failed evidence-recording step does not leave finish_work in an ambiguous partially completed state, or retrying finish_work completes the missing evidence cleanly.
- Recovery guidance names the exact inspection/retry tools needed.
- Tests cover the partial-failure scenario.
- `make check` passes.
