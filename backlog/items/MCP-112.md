# MCP-112 Expose queue continuation metadata

## Goal

Reduce follow-up inspection round trips by making queue responses explicitly name the next ready item and lifecycle weight.

## Implementation Contract

Add deterministic continuation fields to inspect_work_queue and related compact queue outputs, including next_ready_item_id when one exists and a simple lifecycle mode or complexity signal that distinguishes simple direct work from full worker/integration lifecycle work.

## Acceptance

- inspect_work_queue includes next_ready_item_id whenever a runnable item is present.
- Queue item output includes a documented lifecycle or complexity signal derived only from execution_path, planning_gate, and integration state.
- The signal does not choose work for the host model; it only describes the existing workflow path.
- Tests cover direct-ready, worker-handoff, dependency-blocked, and closed-queue states.
