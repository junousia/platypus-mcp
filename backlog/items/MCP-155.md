# MCP-155 Make Pi planning intake-first before mutations

## Goal

Ensure Pi and MCP guidance steer early planning requests through project intake, config-default review, assumptions, questions, and explicit approval before creating backlog items, scaffold files, commits, or implementation artifacts.

## Implementation Contract

Update Pi prompt builders, Pi session guidance, MCP queue/doctor guidance, host guidance docs, and prompt tests so planning discussion is distinct from durable planning artifacts and project-changing actions require explicit user approval in planning contexts.

## Acceptance

- /platy-plan prompts project intake, workflow config review, assumptions, questions, proposed milestone/backlog shape, and approval before backlog creation.
- Pi planning guidance does not instruct implementation or completion from the planning prompt.
- Empty/closed queue and doctor guidance caution that backlog/scaffold mutations require intake and explicit approval.
- Direct-ready guidance preserves implementation flow while warning planning/intake items need scope confirmation before edits or completion.
- Focused Pi tests, guidance/doctor tests, and make check pass.
