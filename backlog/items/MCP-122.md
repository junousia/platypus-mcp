# MCP-122 Make Bazel the primary build and release system

## Goal

Move Platypus MCP to a Bazel-first build and release model suitable for a future multi-component monorepo.

## Implementation Contract

Add Bzlmod-based Bazel configuration using `rules_rust`, crate-universe, and `rules_pkg`. Bazel must build the Rust MCP library and binary, run Rust unit and integration tests, validate formatting, stage release manifests with stamped versions, and provide release artifacts for CI. Update GitHub Actions so code review and publishing use Bazel as the primary build graph.

Cargo and npm manifests remain present because crates.io and npm require them, but release orchestration and version stamping should be driven by Bazel and the Git tag rather than a manual version-preparation commit.

## Acceptance

- `bazel test //...` is the primary full verification command.
- Bazel builds the `platypus-mcp` binary directly through `rules_rust`.
- Bazel test targets cover existing unit and integration test suites.
- Bazel release targets produce stamped `Cargo.toml`, `Cargo.lock`, and `package.json` metadata from the release tag.
- GitHub code review workflow runs Bazel verification instead of Make/Cargo verification.
- GitHub publish workflow derives package versions from tags, builds release binaries through Bazel, publishes crates.io/npm, and creates the GitHub Release after publish succeeds.
- Documentation names Bazel as the normal developer and release entrypoint.
