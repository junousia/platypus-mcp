# MCP-066 Atomic batch backlog item creation

## Goal

Let hosts create related backlog items in one all-or-nothing call instead of many sequential calls.

## Implementation Contract

Add `create_backlog_items` as the batch equivalent of `create_backlog_item`. The operation must pre-validate every requested item, allocate omitted IDs deterministically, resolve intra-batch dependency references, and either write every item or write none. Use a per-item `client_key` plus `depends_on_keys` for dependencies between newly created items in the same batch.

## Acceptance

- A batch can create multiple valid items and return each created item ID, path, client key, and resolved dependencies.
- If any item fails validation, no batch item files are written or modified.
- `depends_on_keys` resolves to IDs allocated or supplied within the same batch.
- Existing `create_backlog_item` defaults and normalization rules are preserved for each batch item.
- Batch failures identify the failing item by index and client key when available.
- Tests cover successful chain creation, explicit IDs, auto-allocated IDs, rollback on unknown epic, rollback on duplicate ID, and rollback on invalid dependency key.
