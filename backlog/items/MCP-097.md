# MCP-097 Reduce backlog authoring and schema discovery friction

## Goal

Remove noisy generated contract prose and expose bounded next-schema hints so agents can use the right tools with fewer cold-start round trips.

## Implementation Contract

When implementation_contract or contract is omitted, keep the required Implementation Contract heading but render an empty section instead of generated warning prose. Add bounded schemas_likely_needed_next hints to inspect_session and inspect_work_queue based on actual queue route, including exact Claude ToolSearch selectors where verified and plain tool names for other hosts.

## Acceptance

- Minimal backlog item creation validates while rendering an empty Implementation Contract section instead of placeholder warning prose.
- Explicit implementation_contract and contract alias behavior remain unchanged, including conflict validation.
- Docs and schema descriptions explain when explicit contracts are recommended without writing fake contract text into product data.
- inspect_session and inspect_work_queue return 1 to 4 bounded schema discovery hints for the likely next phase.
- Claude guidance includes literal ToolSearch selector strings, while Codex and opencode guidance avoids unverified selector syntax.
- Tests cover omitted contract rendering, generated guidance, schema annotations, and schema hint output for empty backlog, direct-ready, planning-blocked, and pending-integration states.
