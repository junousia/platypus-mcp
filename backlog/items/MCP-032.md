# MCP-032 Document distributed storage backend contract

## Goal

Define what a future non-SQLite runtime backend must guarantee before Platypus
can support multiple hosts or shared workers safely.

## Implementation Contract

Document the backend contract for transactions, event ordering, idempotency,
lease semantics, migrations, project identity, conflict handling, and recovery.
Keep SQLite as the reference implementation, but make the distributed-mode
requirements explicit enough that Postgres or another backend can be evaluated
without guessing.

## Acceptance

- Documentation distinguishes repo-owned declarative files from runtime-owned
  mutable state.
- The backend contract states required consistency, ordering, idempotency,
  locking, and migration guarantees.
- Diagrams show local SQLite mode and future shared-backend mode.
- The roadmap identifies the first implementation step toward a second backend
  without committing to one prematurely.
- The docs explain why local-first remains supported even if shared runtime
  backends are added later.

## Notes

Created to prevent SQLite from becoming a hidden product boundary while still
keeping the first implementation pragmatic and local-first.
