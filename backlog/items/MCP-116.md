# MCP-116 Package Platypus MCP binary with npm distribution

## Goal

Make the upcoming npm package self-contained for Pi users by resolving a usable platypus-mcp server binary from the package, while preserving explicit local overrides and development checkout fallbacks.

## Implementation Contract

Define and implement the npm packaging strategy for the Platypus MCP binary. Prefer prebuilt platform-specific npm binary packages or an equivalent package-local binary resolver over postinstall Cargo compilation. Update the Pi extension binary resolution order to try PLATYPUS_MCP_BIN first, then the package-provided platform binary, then the development Cargo.toml fallback, then platypus-mcp on PATH. Add clear error text when no binary is available. Add release/package validation so the npm artifact includes the expected extension files and binary resolver metadata without accidentally shipping build caches or secrets.

## Acceptance

- The Pi npm package can locate a platypus-mcp binary without requiring Cargo for normal installed users.
- PLATYPUS_MCP_BIN remains the highest-priority override for local testing and custom installations.
- Development checkouts still support the existing Cargo.toml fallback.
- Missing or unsupported platform binaries produce actionable install/runtime guidance.
- npm package dry-run or equivalent release validation checks package contents and excludes local caches, target output, secrets, and unrelated repository files.
- Install/release documentation explains the binary packaging model and fallback order.

## Notes

Defer Bazel unless native Cargo/npm release checks become insufficient. Avoid compiling Rust during npm postinstall as the default user path.
