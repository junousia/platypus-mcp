# MCP-118 Publish Pi npm package from GitHub releases

## Goal

Publish the `platypus-pi` npm package from the GitHub release workflow after the Linux and Apple silicon package-local binaries have been built and validated.

## Implementation Contract

Extend the `Publish` workflow so platform binary jobs upload their staged `vendor/<platform>/platypus-mcp` artifacts, then a dedicated npm publish job downloads all required artifacts, validates the combined package with binary presence required for every supported platform, and publishes to npm when a GitHub release is published or a manual non-dry-run dispatch is requested.

Keep manual `workflow_dispatch` dry runs validation-only by default. Require an explicit npm token secret for real publishing, and keep crates.io publishing and npm publishing ordered so the npm package is not published if crates.io validation or publishing fails.

## Acceptance

- Release workflow has a real npm publish job that runs after Rust crate validation/publish and npm binary artifact validation.
- The publish job combines `linux-x64` and `darwin-arm64` binaries into the package-local `vendor/<platform>/platypus-mcp` layout before validation and publish.
- Real npm publish requires a repository secret such as `NPM_TOKEN` and fails clearly when missing.
- Manual workflow dispatch with `dry_run=true` validates npm publish packaging without uploading.
- Makefile exposes npm publish dry-run and publish targets for local/release reuse.
- Documentation explains required npm release secret, dry-run behavior, and the relationship between crates.io and npm release jobs.
