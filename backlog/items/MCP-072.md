# MCP-072 Planning review gate before dispatch

## Goal

Make the boundary between planning and execution explicit for non-trivial work.

## Implementation Contract

Add a lightweight reviewed or approved planning gate without writing runtime status into backlog markdown. Use the existing approval/event/state model where possible. Hosts should be able to request approval for a task plan or backlog tranche, record the approval response, and ask queue/dispatch tools to require approval before dispatching standard or full planning modes.

## Acceptance

- A host can request planning approval for a task plan or backlog tranche.
- Approval responses are stored outside backlog item frontmatter.
- `inspect_work_queue` can require planning approval and report blocked items with recovery guidance.
- `dispatch_ready_work` can require planning approval and refuse unapproved non-direct work.
- `reconcile_project` reports dispatched work that bypassed a required planning gate.
- Tests cover approved dispatch, blocked unapproved dispatch, approval persistence, and no runtime fields added to backlog markdown.
