# MCP-117 Build Apple silicon npm binary package artifact

## Goal

Make the npm package path work for Apple silicon users by producing and validating a `darwin-arm64` Platypus MCP binary artifact that the Pi extension can resolve without requiring Cargo on the user's machine.

## Implementation Contract

Extend the release/package workflow from `MCP-116` to build `platypus-mcp` for Apple silicon, stage it in the package-local resolver layout as `vendor/darwin-arm64/platypus-mcp` or an equivalent platform package artifact, preserve executable permissions, and run strict npm package validation with binary presence required. Keep the resolver fallback order unchanged unless the package shape requires a compatible metadata-only update.

Prefer a GitHub Actions macOS arm64 runner for the native `aarch64-apple-darwin` build. If the workflow uses a platform package such as `@platypus/mcp-darwin-arm64`, document how the main Pi package depends on or discovers it. Do not add postinstall Rust compilation as the normal installed-user path.

## Acceptance

- Release validation builds a `platypus-mcp` binary for Apple silicon using target `aarch64-apple-darwin` or a documented native equivalent.
- The npm package artifact includes an executable Apple silicon binary under the resolver-compatible `darwin-arm64` layout, or publishes an equivalent optional platform binary package documented in package metadata.
- `PLATYPUS_NPM_REQUIRE_BINARY=1 make npm-package` verifies the Apple silicon artifact path or package metadata during release validation.
- The Pi extension can resolve the Apple silicon binary through the existing package-local or optional-package lookup without requiring Cargo.
- Documentation explains the Apple silicon packaging path, expected artifact location, and any signing or notarization limitations left for future work.
- CI/release workflow keeps Linux package validation intact while adding Apple silicon coverage without shipping build caches, secrets, or unrelated repository files.
