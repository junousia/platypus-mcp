# MCP-015 Add storage repository abstraction

## Goal

Reduce handwritten SQL scattered across feature modules by introducing a typed
storage boundary that keeps persistence maintainable as the MCP tool surface
grows.

## Implementation Contract

Evaluate whether this repository should adopt an ORM/query builder such as
SQLx, Diesel, SeaORM, or keep rusqlite behind repository traits. Implement the
first durable boundary around the existing SQLite schema without changing the
external MCP tool contract. Keep transactions explicit, preserve current schema
migrations, and avoid a big-bang rewrite unless the chosen abstraction clearly
reduces risk.

## Acceptance

- Storage access for core runtime records goes through central typed APIs
  instead of direct ad hoc SQL in feature modules.
- The repository documents the ORM/query-builder decision and tradeoffs.
- Existing MCP tool behavior and schemas remain compatible.
- Tests cover at least one migrated read path, one migrated write path, and one
  migration/open path.
- `make check` passes.
