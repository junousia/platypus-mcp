# MCP-070 Dispatch preflight without local agent setup

## Goal

Make dispatch preflight clear without treating missing local agent setup as a
product state. The MCP server should report backlog readiness and lifecycle
state; the host decides which executor to use.

## Implementation Contract

Remove agent-profile readiness from preflight surfaces. `doctor_snapshot`,
`inspect_status`, `inspect_work_queue`, and `dispatch_ready_work` should
distinguish empty backlog, blocked backlog,
missing task plans, and existing active work without requiring local worker
configuration.

## Acceptance

- `doctor_snapshot` does not report missing local manager or worker setup.
- `inspect_work_queue` reports runnable, blocked, active, and prepared work
  without worker readiness fields.
- `inspect_work_queue` recommends host-managed handoff when runnable work exists.
- `dispatch_ready_work` creates or previews host-managed handoffs without local
  worker configuration.
- Tests cover empty backlog, runnable backlog, active work, and dispatch without
  local agent setup.
