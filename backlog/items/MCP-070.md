# MCP-070 Dispatch preflight and no-profile recovery

## Goal

Make missing worker profile configuration visible before dispatch and impossible to misread as an empty backlog.

## Implementation Contract

Add agent-profile readiness to preflight surfaces. `doctor_snapshot`, `inspect_status`, `inspect_work_queue`, `next_safe_action`, and `dispatch_ready_work` should distinguish "no runnable items" from "runnable work exists but no ready worker profile can execute it". Recovery guidance must include concrete `configure_agent_profile` parameters or the explicit manual-handoff path once available.

## Acceptance

- `doctor_snapshot` reports missing manager or worker profiles as warnings with concrete setup guidance.
- `inspect_work_queue` reports worker-profile readiness in preflight warnings.
- `next_safe_action` recommends profile configuration when runnable work exists but no ready worker profile is configured.
- `dispatch_ready_work` does not return only `no_runnable_items` when the real blocker is missing profile readiness.
- No-profile dispatch failures explain whether the caller should configure a worker profile or use manual handoff.
- Tests cover empty backlog, runnable backlog with no profiles, runnable backlog with non-ready profiles, and runnable backlog with ready profiles.
