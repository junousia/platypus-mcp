# MCP-128 Add Pi showcase feedback exercise

## Goal

Create a repeatable exercise that uses Pi as the showcase harness for Platypus-based development and captures feedback on the workflow.

## Implementation Contract

Add a development script and Make target that creates a temporary project, bootstraps Pi and Platypus, initializes the project, asks Pi to perform a small long-term-development workflow, and records the resulting feedback. The prompt should make clear that Platypus is meant for sustainable product development, not a one-shot scaffold shortcut.

The exercise may be skipped or dry-run when Pi is unavailable, but the dry-run must still validate bootstrap, package resolution, project initialization, and core tool availability.

## Acceptance

- A documented `make pi-feedback` or equivalent target creates an isolated temporary project and bootstraps Pi with Platypus.
- Dry-run mode validates setup without invoking a live model.
- Live mode asks for structured feedback on setup, UI, workflow, tool schemas, and completion/closure behavior.
- The script writes a `FEEDBACK.md` file in the temporary project and prints its location.
- The feedback prompt explicitly evaluates long-term product-development workflow quality.
