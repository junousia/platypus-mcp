# MCP-069 Inline validation and rollback for planning writes

## Goal

Guarantee that completed planning write tools leave valid backlog or task-plan state.

## Implementation Contract

Strengthen `create_backlog_item`, `create_backlog_items`, and `write_task_plan` so successful responses imply the relevant validation would pass. Failed writes must preserve the previous file state or remove the invalid new artifact. Validation summaries should be included in successful responses when useful.

## Acceptance

- A completed `create_backlog_item` result implies `validate_backlog` passes for the written item.
- A completed `create_backlog_items` result implies `validate_backlog` passes for the full batch.
- A completed `write_task_plan` result implies `validate_task_plan` passes for the written plan.
- Failed writes do not leave invalid new files behind.
- Failed overwrites restore the previous file content.
- Tests cover successful writes, new-file rollback, overwrite rollback, and validation failure messages.
