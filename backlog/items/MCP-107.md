# MCP-107 Clarify direct completion evidence and closure UX

## Goal

Make complete_backlog_item output and inputs clearer for direct, tool-driven, and traceability-focused work.

## Implementation Contract

Improve direct completion UX around concise status summaries, Git closure commit policy, evidence kind semantics, and empty changed_files/tool-driven completions. Do not silently commit unrelated work; any default or recommendation around commit=true must remain safe and explicit.

## Acceptance

- complete_backlog_item returns a concise status line or compact summary suitable for scripts and humans.
- Tool/schema/docs explain commit=true versus runtime-only closure and why the default is safe.
- Evidence kind semantics are documented in schema or guidance with examples for note, verification, file_summary, worker_finding, manager_disposition, and external_report.
- Direct completion docs include an example for verified non-file or tool-driven work with empty changed_files.
