# MCP-076 Required finding gate semantics

## Goal

Stop forcing agents to mark accepted or deferred required findings as resolved just to pass integration gates.

## Implementation Contract

Keep finding `status` as the semantic disposition. Introduce an explicit gate concept so accepted or deferred required findings can be allowed through integration with an audit reason. Preserve fail-closed behavior for open required findings.

## Acceptance

- Required findings block integration while open.
- Required findings with `accepted`, `deferred`, `resolved`, `rejected`, or `duplicate` no longer block integration.
- Validation output makes the distinction between semantic status and integration blocking clear.
- Tests prove accepted and deferred required findings unblock integration without rewriting them as resolved.
