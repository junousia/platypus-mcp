# MCP-038 Approved external report dispatch boundary

## Goal

Define the mutating MCP boundary for sending or recording external report
actions without embedding provider credentials or network clients in core
runtime behavior.

## Implementation Contract

Sending an external report must be explicit and approval-gated. The first
version should create or consume a durable approval for a drafted report, then
record a host-provided dispatch result with provider, external id, report type,
status, outbound reference, and failure/retry guidance. The tool must not hide
provider writes behind local state changes, and must fail closed if approval
context is missing.

## Acceptance

- A report dispatch request requires a pending approved action or returns a
  structured recovery path.
- Host-provided send results can be recorded durably as events/evidence without
  storing secrets.
- Denied, expired, failed, and retried report attempts are represented
  explicitly.
- Tests cover approved, denied, missing approval, and failed provider-result
  paths without live network calls.
- Documentation makes clear that provider clients live in the host/plugin
  layer until a dedicated safe adapter is added.

## Notes

This item should reuse the existing approval/event/evidence primitives instead
of creating a second reporting state machine.
