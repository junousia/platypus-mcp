# MCP-124 Add typed Pi schemas for core Platypus tools

## Goal

Replace generic passthrough schemas for the most important Pi tools with typed, documented schemas so agents do not have to guess valid fields.

## Implementation Contract

Keep `platypus_call_tool` as an escape hatch, but make the showcase workflow use dedicated Pi tools with explicit TypeBox schemas, useful descriptions, enum values, examples where helpful, and names that match the existing `platypus_*` tool prefix.

Core typed tools should include at least startup inspection, queue inspection, backlog item creation, direct completion, work preparation, worker finish, findings, and diagnostics. The Pi extension must still forward to the Rust MCP tool CLI with the project root fixed to Pi's current working directory.

## Acceptance

- Core Pi tools no longer use a single `additionalProperties` passthrough schema.
- Typed Pi schemas include field descriptions, enum values where applicable, and safe defaults matching the Rust MCP schemas.
- `platypus_call_tool` remains available for non-core tools and debugging.
- Tests or package validation catch accidental regression to generic schemas for the core tool set.
- Documentation names the typed Pi tools that form the normal showcase workflow.
