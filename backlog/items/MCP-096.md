# MCP-096 Enrich direct completion result state

## Goal

Make complete_backlog_item output self-explanatory by returning compact queue state and explicit closure and commit outcomes.

## Implementation Contract

Extend CompleteBacklogItemData additively with a best-effort compact queue_status, queue_status_error, closure details, and commit_outcome details. Preserve existing closed and commit fields. Distinguish runtime direct-completion closure, generated evidence support, and portable Git trailer closure without claiming stronger atomicity than the implementation provides.

## Acceptance

- Successful direct completion returns queue_status with the next ready, blocked, closed, and recommended queue summary when available.
- Queue summary refresh failure does not turn an already successful completion mutation into a failed result; the error is reported separately.
- Completion output states whether commit was requested, created, skipped, or not requested, including reason and commit id when available.
- Closure output distinguishes evidence or runtime-event closure from Git trailer closure and explains portability implications.
- Tests cover evidence-only completion, commit-created completion, already-closed skip behavior, and stdio JSON output.
