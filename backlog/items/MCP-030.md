# MCP-030 Model runtime changes as append-only transitions

## Goal

Make important runtime mutations replayable and auditable so future storage
backends can derive current state from the same event semantics.

## Implementation Contract

Define a small typed transition model for task lifecycle, worker jobs,
approvals, findings, evidence, and integration. Mutating tools should validate
the command, append a durable transition/event, and update any current-state
view transactionally. Keep event payloads bounded and redacted. Do not move
declarative backlog state into the runtime database.

## Acceptance

- Core runtime mutations record typed append-only transitions with stable event
  names and required identifiers.
- Current task, approval, finding, and evidence views remain queryable through
  existing tools.
- Event replay can explain how a task or approval reached its current state.
- Duplicate or invalid transitions fail safely without corrupting current
  state.
- Tests cover replay, derived current state, duplicate handling, and failure
  rollback for at least two runtime domains.

## Notes

This is the event foundation needed before distributed workers or alternate
storage backends can be trusted.
