# MCP-131 Add Pi engineering standards setup

## Goal

Help each Platypus project define how implementation, testing, structure, review, and completion should work before agents start changing code.

## Implementation Contract

Extend the Pi setup flow with engineering standards: module boundaries, code organization, test strategy, required verification commands, UI design language, commit/PR expectations, evidence expectations, and definition of done. These standards should be concise, explicit, and stored in durable project guidance.

Do not hardcode one stack or testing framework. Pi should offer structured prompts and let the manager agent or user decide based on the project context.

## Acceptance

- Pi can collect and persist engineering standards during setup or later steering.
- Generated guidance clearly states implementation structure expectations and test expectations.
- Completion prompts reference the project-specific definition of done.
- Story and implementation review flows can read and summarize the standards.
- Tests cover standards capture, update, and prompt injection.
