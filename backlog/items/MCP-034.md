# MCP-034 Define external intake adapter boundary

## Goal

Make external work import generic and extendable through direct Rust adapters
or future plugins instead of hardcoding GitHub-specific behavior into backlog
tools.

## Implementation Contract

Introduce an adapter boundary that converts external work records into the same
internal draft backlog item shape used by local drafting. The boundary should
define provider identity, capability metadata, candidate listing, item mapping,
deduplication keys, source hashing, and structured import errors. Keep the
first implementation local and in-process, but document how an out-of-process
plugin adapter could satisfy the same contract later.

## Acceptance

- External intake adapters return provider-neutral draft backlog candidates.
- The adapter contract includes provider, kind, external id, source URL or
  locator, source hash, and mapping confidence/reasons.
- Import logic can skip already-imported candidates by external ref identity.
- Provider-specific code is isolated from generic backlog creation and
  validation.
- Tests use a fake adapter to prove candidate mapping, dedupe, and error
  reporting.

## Notes

This should be the extension point for GitHub first and later Linear, Jira,
GitLab, docs, or organization-specific plugins.
