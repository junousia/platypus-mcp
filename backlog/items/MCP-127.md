# MCP-127 Add Pi extension test harness

## Goal

Give the Pi extension enough automated coverage that UI and workflow changes can be made confidently.

## Implementation Contract

Introduce a lightweight TypeScript test setup for the Pi extension using fake Pi APIs, fake command execution, and structured Platypus tool fixtures. Tests should validate tool registration, command behavior, binary resolution guidance, prompt injection, autocomplete, snapshot extraction, and renderer output.

Keep tests local and deterministic. They must not require a live Pi agent, Codex, Claude, opencode, network access, or a published npm package.

## Acceptance

- `make check` or a clearly named Make target runs the Pi extension tests.
- Tests cover successful tool execution, failed tool execution, missing binary guidance, and project-root forwarding.
- Tests cover renderer output for queue status, backlog creation, completion, doctor errors, and empty states.
- Tests cover command prompt generation for start and completion flows.
- Package validation still passes and excludes local test output from npm artifacts.
