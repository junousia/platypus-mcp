# MCP-025 Add strict task plan tooling

## Goal

Add a reviewable, strict YAML task plan artifact for backlog items that need
structured breakdown before work is dispatched.

## Implementation Contract

Create MCP tools to draft, write, inspect, list, and validate task plans under
`backlog/plans/`. Keep runtime state out of plan files; task plans should describe
requirements, design notes, and executable implementation tasks only. Validate
frontmatter and task plan YAML with strict schemas so unknown fields fail fast.

## Acceptance

- `init_project` creates the task plan directory and template.
- MCP hosts can draft, write, inspect, list, and validate task plans.
- Task plan YAML rejects unknown fields, malformed IDs, bad dependencies,
  unknown requirement references, and missing verification or acceptance data.
- Task plan writes stay inside the project root and reject symlink overwrite
  escapes.
- Documentation explains how task plans fit the host workflow.
- `make check` passes.
